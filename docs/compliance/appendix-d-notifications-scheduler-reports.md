# Pulse v3.1 audit: Notifications (§2.2, §3.6), Scheduled jobs (§7), Reports (§4, §8)

Read-only audit of branch `staging` working tree, 2026-10-04. Repo root `C:\Users\91937\Desktop\HRMS\pulse`; all paths below are relative to it. No tests or artisan write commands were run. Only `php artisan route:list` and `php artisan schedule:list` were executed.

**Environment facts**
- The app timezone is `Asia/Kolkata` (`config/app.php:68`; local `.env:6` has `APP_TIMEZONE=Asia/Kolkata`). The production `.env` is UNVERIFIED.
- There is no `app.schedule_timezone` setting and no `->timezone()` call in `routes/console.php`, so the scheduler uses IST. `schedule:list` agrees (the 20:00 job showed "14 minutes from now" at about 19:46 IST).
- All schedules are in `routes/console.php`. `bootstrap/app.php` has no `withSchedule`.
- Seeded shifts (`database/seeders/ShiftSettingSeeder.php:15-28`):
  - IT shift: 10:30–19:30, grace 5, break 60.
  - UK shift: 13:00–22:00 IST, grace 5, break 60.
- The auto-checkout buffer defaults to 30 min (`database/migrations/2026_07_17_235948_...:26`).
- Every scheduled entry has `->withoutOverlapping()`. None has `onOneServer()`, which is acceptable on a single VPS.
- **Mail gate behaviour.**
  - The gate fails open when no settings row exists (`app/Services/Notifications/NotificationDeliveryGate.php:38-40`).
  - The catalog sync creates every event row with `mail_enabled => true` and `is_automatic => true` (`app/Services/Notifications/NotificationCatalog.php:299-309`).
  - The master kill switch defaults to on (`database/migrations/2026_07_03_111002_create_mail_settings_table.php:18`).
- **Synchronous notification classes.** These are not `ShouldQueue`, so their mail goes out inline in whatever process dispatches them, including scheduler batches:
  - ExcessBreak, MissingCheckout, PayslipGenerated, DocumentExpiry, ProbationDue, NewHireCheckIn, OnboardingCompleted, OnboardingTaskOverdue
  - Only these are queued (`tests/Feature/NotificationQueueTest.php`): AttendanceRegularisation, RegularisationReviewed, LeaveRequest, WfhRequest, OtRequest, plus HolidayWorkRequest and Offboarding*.
  - Earlier production SMTP showed `421 too many messages in this connection` on fan-out.
