## Authorization holes

1. **NexflowOtPanel.php:21,31,87-129 (H).** Any `approve-ot` user (every manager) can do two things:
   - Pick any `employeeId`, including their own, and import Nexflow OT as approved, payable OvertimeRecords. There is no scope or self check.
   - Edit the unlocked public `$data` array (for example `data.ot_records.N.status`/`ot_hours`) to create paid OT with any hours they choose.

   Fix: put `#[Locked]` on `$employeeId` and `$data`. In `importRecord`/`importAllApproved`, re-fetch the record from NexflowApiService and call `ApprovalGuard::assertCanDecide(Auth::user(), $employee)`. Limit the panel to `manage_attendance`/`run-payroll`.
2. **CommandCenter.php:84,98,118,137 → `decideOvertime` :238 (M).** OT decisions are gated by `canApproveLeave()`, not `canApproveOt()`. Fix: `abort_unless(Auth::user()->canApproveOt(), 403)` in `decideOvertime`.
3. **AttendanceService.php:428 `rejectRegularisation` (M).** There is no pending check. An in-scope approver can "reject" an already-approved request through TeamAttendance.php:94, AllAttendance.php:500, ApprovalCenter.php:100-112 or LeaveRegularisation.php:160. The status flips, but attendance, OT and leave stay applied. Fix: throw unless `status === 'pending'`.
4. **AllAttendance.php:70-101 `exportCsv` (M).** It is not scoped, so a manager can export the whole company's attendance. Fix: apply `accessibleEmployeeIds()` as `render()` does (:583-591).
5. **ExecutiveAttendance.php:94-110 (M).** Any approve-leave user sees company-wide attendance with names. Fix: filter `$employees` by reach.
6. **BiometricControl.php:53-90 and BiometricSummary.php:57-142 (M).** Data and exports are not scoped. Any manager can run `syncNow`, which reverts regularised days (A-21). Fix: scope by reach and gate `syncNow` to `manage_attendance`.
7. **dashboard-v2 proxy, web.php:275-279 (M; what the engine does is UNVERIFIED).** `set-time`/`pull-logs` are open to any approve-leave user over GET, so they can also be triggered cross-site. Fix: allow read-only paths only; require `manage_biometric` plus POST for device actions.
8. **ManageOtRequests.php:93-134 `openEdit`/`saveEdit` (M).** Approved or paid requests can be edited. There is no same-date duplicate check, and `requested_hours` is not recomputed. Fix: require `isPending()`, recompute the hours and re-run the duplicate check.
9. **AttendanceTracker.php:1897-1903 (M).** Employees can submit regularisations for future dates, times are not validated, and out < in silently becomes an overnight shift that gets OT auto-approved. Fix: `before_or_equal:today`, `date_format:H:i`, and `after:regCheckIn` unless the shift is overnight.
10. **AllAttendance.php:163-211 `submitMarkAttendance` (L/M).** The regularisation row is created before the fast-track permission, self and scope checks. A failure returns a 500 and leaves an orphan pending "[HR — …]" request. Fix: run the checks first and wrap the create in `DB::transaction`.
11. **Director role (Seeder:150-154 + ApprovalGuard) (M, business decision).** Directors can approve and fast-track attendance and OT company-wide, but the spec says "view dept". Fix: set `scope_departments`, or remove the approve permissions.

Checked and safe: `ManageOtRequests::$reviewingId` is `#[Locked]`. `$activeRequest` in TeamAttendance/AllAttendance is a model, and ModelSynth blocks tampering. Every AttendanceService/OvertimeService decision calls `assertCanDecide`, which blocks self-approval and out-of-scope approval. MyOtRequests and the AttendanceTracker actions are scoped to the signed-in employee.
